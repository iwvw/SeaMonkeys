# ADR-0005. 舰船目录：本地版本化元数据 + 静默更新

日期：2026-10-04
状态：Accepted

## 背景

对局元数据只给出数字 `shipId`（如 `3549870064`），需要映射为本地化名称、类型、等级才能展示。

游戏每个大版本会新增舰船。若映射表不更新，新船会显示为"未知船只"。海猴雷达 ApeRadar 的官方船名列表就曾在 13.8 版本后停更，社区被迫写脚本自行生成，说明这是真实的长期维护痛点。

## 决策

**维护本地版本化舰船目录，支持静默自动更新。**

### 1. 目录格式

本地 JSON（示例结构）：

```json
{
  "version": "15.8.0",
  "date": "20261004",
  "ships": {
    "3549870064": {
      "name_zh-cn": "...",
      "name_en-us": "...",
      "type": "Destroyer",
      "tier": 10
    }
  }
}
```

字段：

- `version` / `date`：用于与远端清单比对，判断是否需要更新。
- `ships[id]`：本地化名称（中/英）、类型、等级。

### 2. 语言选择

按用户设置或系统 UI 语言选择 `name_zh-cn` / `name_en-us`，缺失时回退到另一语言，再缺失则显示"未知船只"。

### 3. 更新

- 远端提供一个清单（manifest），含船名表版本与下载地址、哈希。
- 启动时（或定时）比对本地 `date` 与远端，远端更新则下载、校验哈希、替换。
- 静默更新，不打断用户。
- 更新只替换舰船目录文件，绝不触碰用户数据（观察名单、设置、历史）。

### 4. 目录生成（构建期，非运行时）

船名表本身由构建侧脚本从战绩源（如 WG `encyclopedia/ships`）拉取船 ID → 名称/类型/等级，并生成中英映射。运行时只消费生成好的目录文件。

## 备选与未选原因

- **运行时实时查询船名**：每局都要为 24 条船查一次，浪费请求且慢。排除。
- **不更新、手动替换**：正是 ApeRadar 的痛点。排除。
- **打包进应用本体、随应用更新**：船名表更新频率高于应用本体，耦合会导致频繁发版。排除。

## 后果

- 新船不会显示为未知，维护成本低。
- 需要一套远端分发（可复用应用更新的同一代理/CDN）。
- 目录生成脚本是构建期资产，需与游戏版本节奏同步。

## 关联

- ADR-0003（战绩源可用于生成目录）
- CONTEXT 不变量：软件更新绝不覆盖观察名单、窗口位置、日志、截图与下载运行数据
