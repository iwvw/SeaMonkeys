# ADR-0006. 显示形态：常驻置顶悬浮面板

日期：2026-10-04
状态：Accepted

## 背景

用户通常在游戏运行时（多为窗口化/无边框全屏，常配第二块屏）查看战绩。面板需要：

- 快速呼出、不打断游戏操作；
- 在游戏窗口之上可见（但不可注入游戏进程，见 NFR-06）；
- 可长期驻留，占用低。

## 决策

**采用无边框、置顶、可拖动、常驻的独立悬浮窗（WinUI 3），默认贴合屏幕角落，支持多屏与位置记忆。**

### 1. 窗口形态

复用 momomi `MiniWindow` 的成熟做法：

- `OverlappedPresenter` 去边框与标题栏，不可调整大小（或按需允许）。
- `WindowChrome`：工具窗口（不进 Alt+Tab）、圆角、移除非客户区、置顶。
- 位置按 DPI 计算，默认贴合屏幕右下角，支持拖动。
- 位置记忆持久化到用户数据目录。

### 2. 显隐与性能

- 窗口**常驻不销毁**，显隐用 DWM cloak（复用 sox `WindowCloak`），呼出 < 100ms（NFR-03）。
- 全局快捷键呼出/隐藏（复用 sox `HotkeyService`）。
- 托盘常驻（`H.NotifyIcon.WinUI`）。

### 3. 材质

复用 sox 卡片材质架构（`SystemBackdropElement` + Acrylic/Mica + `ThemeShadow`），跟随系统深浅色。

### 4. 内容布局

- 顶部：本局概要（地图、模式、开战时间、区域）。
- 主体：友军 / 敌军两列，每行一名玩家（昵称、公会、舰船、等级、加权胜率、场次），按加权胜率排序，按胜率分色。
- 底部：队伍聚合（平均胜率、战力对比）与输出文本/复制按钮。
- 图表：胜率分布（复用 momomi `SparklineChart` 或等价实现）。

### 5. 全屏游戏处理

复用 sox `FullscreenDetector`：检测到前台全屏窗口时，按设置隐藏面板或降低更新频率，避免干扰。

### 6. 反作弊边界

面板是独立的普通窗口，不注入游戏、不覆盖渲染、不读内存。游戏全屏独占模式下普通置顶窗口可能被遮挡，这是可接受的边界（提示用户使用窗口化/无边框）。

## 备选与未选原因

- **游戏内 overlay（注入）**：有封号风险，违反 NFR-06。排除。
- **纯网页（浏览器 File System Access）**：零安装，但持久化与常驻体验差，且浏览器读本地目录需用户反复授权。作为后续可选形态（PRD F-25）。
- **手机端**：解决单屏问题，但交互与部署成本高。作为后续可选。

## 后果

- 大量 UI 基建直接复用 sox/momomi。
- 全屏独占下无法覆盖游戏，需在文档与 UI 中说明。
- 常驻内存目标 < 300MB（NFR-01）。
